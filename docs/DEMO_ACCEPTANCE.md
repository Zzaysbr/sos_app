# คู่มือเดโมและการตรวจรับล่าสุด

วันที่ 11 พฤศจิกายน 2026 — ดูเหตุการณ์ล่าสุดใน PROJECT_CONTEXT.md ก่อนใช้ตารางนี้ ผลรายงานจากผู้ทดสอบแยกจาก automated tests และหลักฐานฐานข้อมูล

## ผลรอบ build27 วันที่ 11 พฤศจิกายน 2026

- อัปเดตครบ iPhone–iPad–A53 โดยฐานข้อมูลคงเดิม; ทดสอบซอฟต์แวร์737/737 และ build/signature ทั้งสองแพลตฟอร์มผ่าน
- ผู้ทดสอบยืนยันจุดแดง/น้ำเงินทั้งสองฝ่ายอัตโนมัติผ่านตัวกลาง โดยไม่กดแชร์/เลือกผู้รับตำแหน่งหรือคงรายละเอียดไว้
- ล็อกต้นทาง กู้ภัย และเครื่องกลางทีละเครื่อง: ผู้ทดสอบเห็นเวลาพิกัดปลายทางอัปเดต; ล็อกพร้อมกันครบสามเครื่อง: snapshotขณะล็อกยืนยันเวลา/ลำดับพิกัดรับใหม่ทั้งสองทิศทางในช่วงที่ตรวจ (warm process/ต่อสายตรวจ)
- ปิด–เปิด Bluetooth A53: เชื่อมกลับเอง ข้อความค้างถึงครั้งเดียวพร้อม Sent และพิกัดทั้งสองฝ่ายอัปเดตต่อเอง
- ปิด SOS: ผู้ทดสอบยืนยันเอาเหตุออกจาก Helping และประวัติ/แชท/สื่อเดิมยังเปิดได้; A53 snapshotยืนยันสถานะ cancelled และ location foreground service หยุด ส่วน BLE service ยังเปิดตามหน้าที่รับ/ส่งต่อ
- ยังไม่ผ่านการตรวจการเคลื่อนที่จริงเพราะพื้นที่จำกัด, ระยะวิทยุขาดจริง, long-idle/Doze soak หรือ process kill; จุดกู้ภัยหลังรับเหตุไม่ใช่หลักฐานการปรากฏสถานะบนเครื่องอื่นทันทีที่เปิดโหมดกู้ภัยก่อนรับเหตุ

## ชุดเดโมหลัก

A = iPhone ผู้ขอความช่วยเหลือ, B = iPad ตัวกลาง, C = A53 กู้ภัย เปิดแอปค้าง ใช้ข้อมูลสังเคราะห์ ตั้ง consent การส่งต่อ SOS/voluntary rescue บน A และการส่งต่อบน B/C ให้ถูกต้อง ปิดอินเทอร์เน็ตและ Wi-Fi ระหว่างเดโม BLE

1. ปิด Bluetooth B ชั่วคราว เชื่อม A–C สร้าง SOS ใหม่ครั้งเดียว C เปิดรับเหตุ/รับช่วยเหลือ แล้วส่งข้อความตรงหนึ่งครั้ง
2. เลิกเชื่อม A–C โดยไม่ยกเลิกเหตุ ตรวจว่าเหตุถูกซ่อนเมื่อขาดการติดต่อ
3. เปิด Bluetooth B เชื่อม B–C แล้ว A–B เว้น A–C เหตุเดิมต้องกลับมาโดยไม่กดรับใหม่ ตรวจเส้นทางล่าสุด3เครื่อง/2hops
4. ส่งข้อความไปกลับครั้งละหนึ่งข้อความ ตรวจไม่ซ้ำและสถานะส่งแล้ว
5. ส่งรูปและวิดีโอสั้น3–5วินาทีไปกลับทีละไฟล์ จดขนาดหลังเตรียมไฟล์ เวลาตั้งแต่ยืนยันจนพร้อมเปิด เสียง/ภาพ และ final receipt
6. A กดค้างปิด SOS ตรวจ C เอาเหตุออก จากนั้นเปิดประวัติ/แชท/ไฟล์ทั้งสองฝั่ง
7. เปิดอินเทอร์เน็ตเฉพาะการตรวจสมาชิก กด Sync แล้วตรวจประวัติ/สื่อซ้ำ ไม่ต้องส่งไฟล์ใหม่

การเลิกเชื่อมจำลองการตัดเส้นทาง ไม่ใช่หลักฐานระยะวิทยุจริง เส้นทางบน UI เป็นหลักฐานล่าสุดที่บันทึก ไม่ใช่แผนผังวิทยุแบบรับประกันเวลาจริง

## แผนที่และตำแหน่ง: ขั้นตรวจถัดไป

- อัปเดตเครื่องให้รุ่นเดียวกัน เปิด Location Services/สิทธิ์ตำแหน่งตามการใช้งานจริง
- ขณะมีอินเทอร์เน็ตเปิดแผนที่และดาวน์โหลดบริเวณเล็กที่ครอบคลุมจุดเดโมด้วย provider ที่รองรับ ตรวจจำนวน tile/ขอบเขต/zoom ที่เก็บ แล้วปิดอินเทอร์เน็ต
- เปิด SOS สังเคราะห์ ให้ C รับช่วยเหลือ ตำแหน่งเริ่มอัปเดตอัตโนมัติบน build27 โดยไม่เลือกเครื่องรับพิกัด (ยังต้องอนุญาตตำแหน่งจากระบบ และเคารพการแนบพิกัดสาธารณะของ SOS)
- เปิด Map จากแชทหรือรายละเอียด ไม่ต้องคงหน้ารายละเอียดเพื่อให้การแชร์ทำงานบน build27 ตรวจจุดแดงผู้ขอความช่วยเหลือและจุดน้ำเงินกู้ภัย รวมถึงตำแหน่งตนเอง ขยับ C ระยะสั้นที่ GPS แยกได้โดยไม่ต้องทำให้ Bluetooth หลุด
- จดเวลาที่จุดของ C เปลี่ยนบนเครื่อง C และ A ผ่าน B ตรวจว่าพิกัดเก่าถูกระบุอย่างถูกต้องเมื่อหยุดรับอัปเดต
- ออกจากหน้ารายละเอียดและกลับแผนที่ ตรวจว่ายังได้รับพิกัดใหม่; ปิด SOS/เลิกติดตามเหตุแล้วตรวจว่าหยุดส่ง โดยประวัติ/แชท/สื่อยังอยู่
- ทดสอบล็อกจอต้นทาง ตัวกลาง ปลายทาง ทีละเครื่อง แล้วล็อกครบทั้งสามในเหตุเดิม จดเวลาพิกัดก่อน/หลังและตรวจด้วยจุดที่ขยับจริง; การผ่าน foreground ไม่เท่ากับผ่าน background
- build27 ใช้ location stream ที่เปิดจาก foreground, Android location FGS + BLE service CPU lock และ iOS location/Bluetooth modes + finite BLE-event execution budget ไม่มีข้อรับรอง force-quit/OS-kill หรือการค้นพบ iOS ที่เริ่มประกาศตัวใหม่ขณะอยู่ background โดย Android

## ความทนทานและ notification

ทำทีละกรณีบนเหตุทดสอบใหม่: ล็อกจอ/ออกแอป, ข้อความใหม่และ system notification, ปิด Bluetooth C ระหว่างส่งไฟล์แล้วเปิดกลับ, ยกเลิก SOS ขณะ C ขาดลิงก์ แล้วเชื่อมกลับ ตรวจไฟล์/receipt/สถานะเหตุอย่างละหนึ่งครั้งก่อนลองซ้ำ ถ้าล้มเหลวเก็บเวลา รุ่น/บทบาทเครื่อง และคิว/log ก่อนรีสตาร์ท ไม่ส่งซ้ำเพื่อกลบอาการ

iOS force-quit/OS-kill ไม่ได้รับรองจากการทดสอบ foreground และการประกาศ Bluetooth background modes เพียงอย่างเดียว

## การเก็บหลักฐาน

บันทึกเลข build ทุกเครื่อง, บทบาท, เครือข่ายที่เปิด/ปิด, คู่เชื่อม, incident/message test IDs, จำนวนที่รับจริง, ขนาด byte/เวลา/receipt และภาพหน้าจอที่ไม่มีข้อมูลส่วนตัว อย่า commit ไฟล์สื่อส่วนตัว ฐานข้อมูลจากเครื่อง หรือคีย์ provider ลง Git
