## ชุดเดโมหลัก

A = iPhone ผู้ขอความช่วยเหลือ, B = iPad ตัวกลาง, C = A53 กู้ภัย เปิดแอปค้าง ใช้ข้อมูลสังเคราะห์ ตั้ง consent การส่งต่อ SOS/voluntary rescue บน A และการส่งต่อบน B/C ให้ถูกต้อง ปิดอินเทอร์เน็ตและ Wi-Fi ระหว่างเดโม BLE

1. ปิด Bluetooth B ชั่วคราว เชื่อม A–C สร้าง SOS ใหม่ครั้งเดียว C เปิดรับเหตุ/รับช่วยเหลือ แล้วส่งข้อความตรงหนึ่งครั้ง
2. เลิกเชื่อม A–C โดยไม่ยกเลิกเหตุ ตรวจว่าเหตุถูกซ่อนเมื่อขาดการติดต่อ
3. เปิด Bluetooth B เชื่อม B–C แล้ว A–B เว้น A–C เหตุเดิมต้องกลับมาโดยไม่กดรับใหม่ ตรวจเส้นทางล่าสุด3เครื่อง/2hops
4. ส่งข้อความไปกลับครั้งละหนึ่งข้อความ ตรวจไม่ซ้ำและสถานะส่งแล้ว
5. ส่งรูปและวิดีโอสั้น3–5วินาทีไปกลับทีละไฟล์ จดขนาดหลังเตรียมไฟล์ เวลาตั้งแต่ยืนยันจนพร้อมเปิด เสียง/ภาพ และ final receipt
6. A กดค้างปิด SOS ตรวจ C เอาเหตุออก จากนั้นเปิดประวัติ/แชท/ไฟล์ทั้งสองฝั่ง
7. เปิดอินเทอร์เน็ตเฉพาะการตรวจสมาชิก กด Sync แล้วตรวจประวัติ/สื่อซ้ำ ไม่ต้องส่งไฟล์ใหม่

การเลิกเชื่อมจำลองการตัดเส้นทาง ไม่ใช่หลักฐานระยะวิทยุจริง เส้นทางบน UI เป็นหลักฐานล่าสุดที่บันทึก ไม่ใช่แผนผังวิทยุแบบรับประกันเวลาจริง

## แผนที่และตำแหน่ง: ขั้นตรวจถัดไป

- อัปเดตเครื่องให้รุ่นเดียวกัน เปิด Location Services/สิทธิ์ตำแหน่งตามการใช้งานจริง
- ขณะมีอินเทอร์เน็ตเปิดแผนที่และดาวน์โหลดบริเวณเล็กที่ครอบคลุมจุดเดโมด้วย provider ที่รองรับ ตรวจจำนวน tile/ขอบเขต/zoom ที่เก็บ แล้วปิดอินเทอร์เน็ต
- เปิด SOS สังเคราะห์ ให้ C รับช่วยเหลือ และเปิดการแชร์ตำแหน่งโดยยินยอมในรายละเอียดเหตุทั้งสองฝ่ายตามต้องการ
- จากรายละเอียดเปิด Map โดยคงหน้ารายละเอียดไว้ข้างใต้ (build25) ตรวจจุดแดงผู้ขอความช่วยเหลือและจุดน้ำเงินกู้ภัย รวมถึงตำแหน่งตนเอง ขยับ C ระยะสั้นที่ GPS แยกได้โดยไม่ต้องทำให้ Bluetooth หลุด
- จดเวลาที่จุดของ C เปลี่ยนบนเครื่อง C และ A ผ่าน B ตรวจว่าพิกัดเก่าถูกระบุอย่างถูกต้องเมื่อหยุดรับอัปเดต
- ปิดการแชร์แล้วตรวจว่าไม่มีการส่งพิกัดใหม่ การแชร์ในหน้ารายละเอียดนี้สิ้นสุดเมื่อปิดหน้ารายละเอียด; ยังไม่ใช่หลักฐาน always-on/background location

## ความทนทานและ notification

ทำทีละกรณีบนเหตุทดสอบใหม่: ล็อกจอ/ออกแอป, ข้อความใหม่และ system notification, ปิด Bluetooth C ระหว่างส่งไฟล์แล้วเปิดกลับ, ยกเลิก SOS ขณะ C ขาดลิงก์ แล้วเชื่อมกลับ ตรวจไฟล์/receipt/สถานะเหตุอย่างละหนึ่งครั้งก่อนลองซ้ำ ถ้าล้มเหลวเก็บเวลา รุ่น/บทบาทเครื่อง และคิว/log ก่อนรีสตาร์ท ไม่ส่งซ้ำเพื่อกลบอาการ

iOS force-quit/OS-kill ไม่ได้รับรองจากการทดสอบ foreground และการประกาศ Bluetooth background modes เพียงอย่างเดียว

## การเก็บหลักฐาน

บันทึกเลข build ทุกเครื่อง, บทบาท, เครือข่ายที่เปิด/ปิด, คู่เชื่อม, incident/message test IDs, จำนวนที่รับจริง, ขนาด byte/เวลา/receipt และภาพหน้าจอที่ไม่มีข้อมูลส่วนตัว อย่า commit ไฟล์สื่อส่วนตัว ฐานข้อมูลจากเครื่อง หรือคีย์ provider ลง Git
