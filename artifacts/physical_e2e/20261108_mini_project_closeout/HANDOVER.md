# รายงานส่งมอบชุดสาธิต Emergency

> สถานะล่าสุด: **ยังไม่ครบข้อกำหนดมินิโปรเจกต์** ผู้ใช้ยืนยันหลังรายงานนี้ว่าต้องมีแผนที่ออฟไลน์ และ Chat ส่งรูป/วิดีโอจากทั้งกล้องและคลัง ข้อความที่ระบุว่ารูป/วิดีโอไม่รวมในเดโมด้านล่างเป็นขอบเขตของ build 5 เดิม ไม่ใช่การอนุมัติให้ตัดออกจากงานส่ง โค้ดกำลังเปลี่ยนเพื่อเพิ่มสื่อ ดังนั้นผล hash เดิมใน FINAL_REVIEW.json เป็นหลักฐาน ณ เวลารวบรวมเท่านั้น ไม่ใช่สถานะโค้ดใหม่

วันที่ 8 พฤศจิกายน 2026 (Asia/Bangkok) — Flutter `0.1.0+5`, SQLite schema v10

ชุดนี้มีหลักฐานรองรับการสาธิต SOS/BLE, Help Offer, Chat พร้อมใบรับการเก็บข้อความ, การยกเลิกเหตุ และการหยุดติดตามเฉพาะเครื่อง ตามกรณีที่ระบุด้านล่าง ไม่ใช่การรับรองบริการฉุกเฉินหรือการผ่าน rubric ที่ยังไม่ได้รับ

## ตัวโค้ดและการสร้างซ้ำ

- `../20261108_final_chat_receipt/source_manifest.json`: รายการ hash ของ source/config 148 ไฟล์ที่ผูกกับ build 5
- `../20261108_final_chat_receipt/test_manifest.json`: รายการ hash ของไฟล์ทดสอบ 73 ไฟล์
- `FINAL_REVIEW.json`: ผลเทียบไฟล์ปัจจุบันกับรายการข้างต้น และ hash ของเอกสาร/ตัวช่วยทดสอบที่เพิ่มในรอบปิดงาน
- `../20261108_final_chat_receipt/BUILDS.json`: hash ของ APK และ iOS bundle พร้อมหลักฐานติดตั้งทับทั้งสามเครื่องในโฟลเดอร์เดียวกัน

ตรวจซ้ำแล้ว source/config และ test ทุกไฟล์ในรายการยังตรง build 5 ไม่มีการแก้แอปหรือติดตั้งรุ่นใหม่ระหว่างการตรวจปิดงาน การแก้ README, เอกสารและตัวเรียก emulator ไม่ได้เปลี่ยนไบนารีแอป

working tree มีการแก้ไขและลบไฟล์จำนวนมากที่มีมาก่อนรอบนี้ จึงไม่ได้รวมทั้งหมดเป็น commit ส่งมอบ และ HEAD เพียงอย่างเดียวสร้างชุดที่ทดสอบซ้ำไม่ได้ ให้ใช้ working tree ร่วมกับ manifest ห้ามใช้รายงานนี้แทน source archive หรือ commit ที่เก็บไฟล์ครบ การสร้างซ้ำบน iOS ยังต้องมี signing และ configuration ของผู้สร้างตามปกติ

## ผลตรวจที่รองรับ

| เรื่อง | ผลและขอบเขตหลักฐาน |
|---|---|
| Automated app checks | build 5 มี default suite 594 ผ่าน, receipt/explicit contract 8 ผ่าน และ static analysis ไม่มีปัญหา ตาม `../20261108_final_chat_receipt/VALIDATION.json`; ไม่ได้รัน suite ทั้งหมดซ้ำในรอบเอกสารนี้ |
| Guest/account host checks | รันเพิ่ม 33 ผ่าน ครอบคลุม session/history/sync/recovery ที่ใช้ mock; ไม่ใช่ live email/cloud |
| Firestore rules | isolated local emulator 8 ผ่าน และตัวเรียกใช้พอร์ตว่างรันซ้ำ 8 ผ่าน; ไม่ deploy หรือรับรอง rules ที่ใช้งานจริง |
| Offline BLE คู่ iPhone–Samsung | Chat ไปกลับเห็นฝั่งรับครั้งเดียว พร้อม signed final persistence receipt ที่ตรวจเทียบและตรวจลายเซ็นจาก snapshot; Bluetooth outage หนึ่งกรณีกลับมาส่งข้อความเดิมได้โดยไม่ส่งซ้ำ |
| ส่งผ่าน Samsung ระหว่าง iPhone–iPad | สลับ Bluetooth ปลายทางไม่ให้เปิดพร้อมกัน; ตรวจ signed SOS path, Offer/ACK, Chat/receipt สองทิศทางและ cancellation จากฐานข้อมูลที่สัมพันธ์กัน รองรับหนึ่งรอบแบบเก็บรอส่งต่อ ไม่ใช่ topology พร้อมกันหรือการทดสอบระยะ |
| หยุดติดตาม | iPad เหตุเก่า 7 รายการออกจาก Helping ประวัติ/Chat คงอยู่ และไม่กลับมาหลังอัปเดต; มีทั้ง snapshot เดิมและผลผู้ใช้ยืนยัน |
| ตำแหน่ง iPhone | เคยขึ้น Location request timed out แม้ผู้ใช้ยืนยันสิทธิ์ครบ; ต่อมา Apple Maps แสดงตำแหน่ง, Emergency พบ Current location และหลังรีสตาร์ทเปิด Emergency ก่อน Maps ก็พบ Current location พร้อมประวัติครบ ผลเป็นผู้ใช้รายงาน ไม่ได้ตรวจ raw fix/accuracy; ยังไม่ทราบสาเหตุ timeout |
| ล็อกจอและกลับเข้าแอป | หนึ่งรอบต่อทิศทาง: ล็อกเครื่องรับ 2 นาที ส่งข้อความครั้งเดียว รอ 30 วินาทีแล้วกลับเข้า Chat; ผู้ใช้ยืนยันเห็นข้อความ 1 ครั้ง และผู้ส่งขึ้น Confirmed stored ทั้งสองฝั่ง ไม่ได้แยกว่ารับขณะล็อกหรือหลังเปิดแอป และไม่มี snapshot ใหม่ในรอบนี้ |
| บัญชี/Guest บน Samsung | ผู้ใช้ยืนยันบัญชีทดสอบ → Guest → กลับบัญชีเดิมสำเร็จ ประวัติบัญชีปกติและ Guest เดิมอยู่; รายละเอียด Guest แสดง Device only ไม่มีแก้ไข/ยกเลิก/ลบ ไม่ใช่หลักฐานแยกบัญชีคนละคนหรือข้อมูลบน server |
| Samsung ภาษาไทย/ตัวอักษรใหญ่ | ผู้ใช้ยืนยัน Settings, History, รายละเอียด Guest อ่านได้ ปุ่มใช้ได้ เลื่อนได้หลังเพิ่มขนาดตัวอักษร; ไม่ได้บันทึกค่า scale หรือรับรองทุกหน้าที่ขนาดสูงสุด |
| Samsung แผนที่ออนไลน์ | ผู้ใช้ยืนยันเหตุเก่ามีพื้นแผนที่ หมุด และเลื่อน/ซูมได้ ไม่รับรองตำแหน่งจริงหรือแผนที่ออฟไลน์ |
| iPad ภาษาอังกฤษ | ผู้ใช้ยืนยัน Settings, Helping, ประวัติผู้ช่วยและรายละเอียดเหตุที่หยุดติดตามแสดงปกติ เหตุเก่าอยู่เฉพาะประวัติ ไม่กลับ Helping |

ผลผู้ใช้ยืนยันและสถานะล่าสุดเก็บใน `CHECKLIST.json`; หลักฐาน physical BLE/crypto โดยละเอียดอยู่ใน `../20261108_final_chat_receipt/DEVICE_RETEST.json` และ `STAGED_C_FINAL_CORRELATION.json` รวมถึงไฟล์ที่อ้างอิงจากรายงานเหล่านั้น ห้ามเพิ่มพิกัด ข้อมูลบัญชี หรือฐานข้อมูลดิบลงชุดเผยแพร่

## สาธิตและตรวจซ้ำ

ทำตาม README ที่ root สำหรับคำสั่งทดสอบและลำดับ SOS → Offer → Chat → cancellation ใช้ข้อความทดสอบครั้งเดียวต่อกรณี การส่งหลายทอดต้องใช้ขั้นแยก Bluetooth ปลายทางตามหลักฐานเพื่อพิสูจน์การผ่านตัวกลาง

หลังรอบล่าสุดไม่มี SOS ทดสอบที่ยัง active ตามผลผู้ใช้ยืนยัน Samsung กลับเข้าบัญชีและเปิดอินเทอร์เน็ตแล้ว; iPhone เป็น Guest และ iPad Bluetooth ปิดตามการยืนยันล่าสุด ยังไม่ได้ยืนยันการคืนค่าเครือข่ายทุกเครื่องหรือขนาดตัวอักษร Samsung กลับค่าเดิม ผู้ใช้สามารถคืนค่าตามการใช้งานปกติได้

## รายการที่ต้องตกลงก่อนประกาศปิดมินิโปรเจกต์ทั้งหมด

1. เทียบ rubric จริงกับชุดสาธิตนี้ ยังไม่มี rubric ให้ตรวจ หากต้องการ source archive/commit, วิดีโอ, สไลด์หรือรายงานรูปแบบเฉพาะ ต้องจัดให้ครบตามข้อกำหนดนั้น
2. รับทราบข้อจำกัดที่ยังเปิด: GPS timeout เป็นครั้งคราวที่ยังหาสาเหตุไม่ได้, location-bearing SOS บน build สุดท้ายยังไม่มีผลยืนยันจากรอบนี้, long-idle/OS-kill, แยกบัญชีต่างคน/ข้อมูล cloud และ deployed rules, live recovery/email, offline map downloads และข้อจำกัดของ signed receipt
3. รูป/วิดีโอใน Chat, E2EE, LoRa และ Store distribution ไม่รวมในชุดสาธิตปัจจุบัน จะตัดออกจากงานส่งได้เมื่อข้อกำหนดรายวิชาอนุญาต

Confirmed stored หมายถึงหลักฐานเครื่องปลายทางเก็บข้อความ ไม่ได้หมายถึงมีคนอ่านหรือหน่วยกู้ภัยรับงาน ไม่มีการรับประกันส่งถึงหรือ global exactly-once
